📖 이 사이트의 사용법

각 챕터는 독립된 mini 사이트다. 카드를 누르면 그 챕터의 표지로 이동하고, 표지에서 다시 패턴별 sub-chapter로 들어간다. 모든 패턴은 같은 순서로 풀린다 — 의도 → 왜 필요한가(동기) → 구조(UML) → 참여자 → 결과(장단점) → 코드 → 시험 함정.

이 과목의 핵심은 패턴 이름을 외우는 것이 아니라, 설계 문제가 생겼을 때 적절한 패턴으로 구조를 재편하는 판단력이다. 그래서 본문은 늘 “왜 이 구조인가”를 먼저 설명하고, 헷갈리는 패턴 쌍(Strategy vs State 등)을 끝까지 비교한다. UML은 클래스 다이어그램으로, 핵심은 Java 코드 스케치로 보여 준다.

🚀 시험 우선순위 추천 경로

  1. Ch.4 행위 패턴 — Strategy · State · Command · Observer · Template Method · Iterator. 가장 많이 나오고, 헷갈리는 쌍이 몰려 있다.
  2. Ch.2 생성 패턴 — Singleton · Factory Method · Abstract Factory. 정의와 구분(FM vs AF)이 단골.
  3. Ch.3 구조 패턴 — Adapter · Decorator · Composite. Decorator vs 상속, Adapter vs Decorator 구분.
  4. Ch.6 패턴 선택 · 비교 — 시나리오→패턴 의사결정 + 헷갈리는 6쌍. 응용 문제 대비 1순위.
  5. Ch.1 토대 · Ch.5 시스템/객체 설계 — 패턴을 받치는 원칙(인터페이스 의존, 합성>상속)과 설계 활동.
