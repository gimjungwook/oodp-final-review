Chapter 05 · 시스템 · 객체 설계

큰 덩어리로 나누고
모델을 코드로

분석에서 구현으로 넘어가는 다리 구성 2 sub-chapter 범위 System Design · Object Design

이 장을 왜 읽는가

패턴이 작은 구조의 재사용이라면, 이 장은 전체 시스템 분해와 모델에서 코드로의 매핑을 다룬다. 앞 장들의 디자인 패턴은 "이미 클래스 단위로 쪼개진 작은 구조를 어떻게 변경에 강하게 짤 것인가"에 집중했다. 그러나 그 작은 구조들이 자리잡으려면, 먼저 시스템 전체가 응집도 높고 결합도 낮은 서브시스템으로 나뉘어 있어야 하고, 분석 단계의 추상 모델이 실제로 컴파일되고 실행되는 코드로 옮겨져야 한다.

두 단계는 책임의 크기로 갈린다. 시스템 설계(System Design)는 분석(무엇을)에서 구현(어떻게)으로 넘어가는 다리로, 시스템을 큰 덩어리(서브시스템)로 나누고 아키텍처 스타일과 설계 목표를 결정한다. 객체 설계(Object Design)는 그 안에서 분석 객체 모델을 연관, 계약, 인터페이스, 최적화의 네 작업으로 실제 코드에 매핑한다. 바로 이 객체 설계 단계에서 앞 장의 디자인 패턴이 투입된다.

PART · 설계의 두 층위

이 챕터는 시스템 설계(ch6)와 객체 설계(ch8) 강의를 바탕으로, 패턴이 어느 단계에 어떻게 투입되는지를 연결한다. 두 sub-chapter는 "정의보다 왜"를 먼저 다룬다.
